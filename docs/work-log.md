# Журнал выполненной работы

Я проверил утилиту диагностики на CentOS Stream 10 и Windows-хосте. Сводка — в [README](../README.md).

## 1. Окружение и версия скрипта

**Задача:** связать исходный код с сохранёнными запусками.

**Что сделал:** проверил версии Python и systemd, синтаксис, справку и версию утилиты. Сравнил SHA-256 файла на хосте и ВМ. Позже я восстановил исходную версию с ВМ и подготовил вариант без комментариев и docstring.

**Результат и проблемы:** исторические хеши хоста и ВМ совпали: `c9b8e118…`. У опубликованной версии после небольшого изменения структуры ради улучшения читаемости другой хеш — `f76c77f6…`; для неё я сохранил запуск `--version` и проверку диска.

**Подтверждение:** [окружение](../evidence/env/), [версии скрипта](../evidence/diag/08-script-versions.txt), [исходный код](../src/diagnose.py).

## 2. Проверка рабочего сервера

**Задача:** проверить нормальное состояние и оба формата вывода.

**Что сделал:** запустил проверки службы, порта, HTTP и диска. Проверил наличие `Test site` в HTTP-ответе. Отдельно добавил `config` с root и выполнил сетевые проверки с хоста.

**Результат и проблемы:** выбранные проверки успешны, код 0. Текстовый режим не мешает сохранению JSON через `--output`. На Windows проверка службы вернула `error` и код 3 из-за отсутствия `systemctl`.

**Подтверждение:** [локальный запуск](../evidence/diag/01-baseline-local.txt), [текстовый режим](../evidence/diag/02-baseline-text.txt), [проверка конфига](../evidence/diag/03-baseline-with-config.txt), [с хоста](../evidence/diag/04-baseline-remote-host.txt), [служба на Windows](../evidence/diag/05-service-on-host.txt), [её JSON](../evidence/diag/05-service-on-host.json).

## 3. Остановка Nginx

**Задача:** проверить обнаружение остановленной службы.

**Что сделал:** проверил диагностику после остановки Nginx, состояние службы и журнал. Повторил сетевую проверку с хоста, затем проверил восстановленный сервер.

**Результат и проблемы:** служба стала `inactive (dead)`, TCP и HTTP получили отказ соединения, утилита вернула код 1. После запуска сервера проверки снова завершились с кодом 0. Значение `Result=success` у остановленной службы не означает, что она сейчас работает.

**Подтверждение:** [диагностика](../evidence/diag/10-nginx-stopped.txt), [status](../evidence/diag/11-status-stopped.txt), [журнал](../evidence/diag/12-journal-stopped.txt), [с хоста](../evidence/diag/14-nginx-stopped-remote-host.txt), [восстановление](../evidence/diag/13-nginx-restored.txt).

## 4. Блокировка HTTP в firewalld

**Задача:** отличить локальную работоспособность сайта от его доступности по сети.

**Что сделал:** проверил зону без сервиса http, запустил диагностику локально и с хоста, дополнительно проверил запрос через `curl.exe`. После возврата http повторил удалённую диагностику.

**Результат и проблемы:** локальная проверка осталась успешной. С хоста TCP и HTTP завершились по тайм-ауту, код утилиты — 1; после возврата http получен код 0. Сам по себе тайм-аут не устанавливает причину отказа, поэтому я сохранил состояние firewalld до и после.

**Подтверждение:** [зона без http](../evidence/diag/20-firewall-http-removed.txt), [локально](../evidence/diag/21-fw-blocked-local.txt), [с хоста](../evidence/diag/22-fw-blocked-remote-host.txt), [curl](../evidence/diag/23-fw-blocked-curl-host.txt), [возврат http](../evidence/diag/24-firewall-restored.txt), [успешный повтор](../evidence/diag/25-fw-restored-remote-host.txt).

## 5. Ошибка конфигурации Nginx

**Задача:** сравнить последствия reload и restart при неверном конфиге.

**Что сделал:** проверил конфигурацию с `bogus_directive`, выполнил reload и диагностику с `config`. Затем проверил restart с той же ошибкой, исправил конфиг и сравнил его с сохранённым рабочим файлом.

**Результат и проблемы:** `nginx -t` обнаружил неизвестную директиву. После неуспешного reload сайт продолжил отвечать, но проверка `config` вернула `fail`. После restart служба перешла в `failed`, TCP и HTTP стали недоступны. После исправления diff не показал различий, все пять проверок прошли.

**Подтверждение:** [nginx -t](../evidence/diag/30-nginx-t-broken.txt), [reload](../evidence/diag/31-reload-broken.txt), [error.log](../evidence/diag/32-error-log.txt), [после reload](../evidence/diag/33-config-broken-after-reload.txt), [restart](../evidence/diag/34-restart-broken.txt), [после restart](../evidence/diag/35-config-broken-after-restart.txt), [исправление](../evidence/diag/36-nginx-t-fixed.txt), [diff](../evidence/diag/37-diff-vs-good.txt), [итог](../evidence/diag/38-config-restored.txt), [аудит](../evidence/diag/39-audit-trail.txt).

## 6. Отказ SELinux

**Задача:** проверить обнаружение HTTP 403 при работающем Nginx.

**Что сделал:** сохранил результат диагностики и AVC для страницы с типом `var_t`, затем проверил сервер после исправления.

**Результат и проблемы:** служба и TCP остались доступны, HTTP вернул 403, итоговый код — 1. Обычный `ls -Z` не смог прочитать путь; причину со стороны SELinux подтвердил AVC с `httpd_t`, `var_t` и `permissive=0`. После исправления диагностика вернула код 0.

**Подтверждение:** [ls](../evidence/diag/40-label-broken.txt), [HTTP 403](../evidence/diag/41-selinux-403.txt), [AVC](../evidence/diag/42-avc.txt), [восстановление](../evidence/diag/43-selinux-restored.txt).

## 7. Порог диска и ошибки входных данных

**Задача:** проверить коды 1, 2 и 3 на отдельных сценариях.

**Что сделал:** поднял минимальный порог свободного места до 99%, передал неверный порт и имя проверки, затем проверил порт неизвестного хоста.

**Результат и проблемы:** при 90.6% свободного места порог 99% дал код 1 без заполнения диска. Неверные аргументы дали код 2 без JSON; это согласованное исключение из пар файлов. Неизвестный хост дал `error`, итог `unknown` и код 3. В ранних записях `rec` печатала команды без кавычек; позже я исправил запись через `%q`.

**Подтверждение:** [диск](../evidence/diag/50-disk-threshold.txt), [порт](../evidence/diag/51-bad-port.txt), [неизвестный хост](../evidence/diag/52-unknown-host.txt), [имя проверки](../evidence/diag/53-bad-check.txt).
