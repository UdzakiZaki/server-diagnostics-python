# Диагностика Linux-сервера на Python

Я написал утилиту [diagnose.py](src/diagnose.py) для проверки службы, TCP-порта, HTTP-ответа, свободного места и конфигурации Nginx. Она выводит JSON или текстовую сводку, сохраняет JSON через `--output` и возвращает коды 0/1/2/3. Проверил её на работающем сервере и при нескольких видах отказа.

## Окружение

Я использовал Windows с PowerShell и ВМ CentOS Stream 10 в VirtualBox. На ВМ установлен Python `3.12.15`, на Windows-хосте — `3.12.10`; systemd на ВМ — `257-34.el10-g359ab09`. Версии сохранены в [evidence/env](evidence/env/). В HTTP-ответах Nginx указана версия `1.26.3`, сайт находится в `/srv/site`.

Службу и конфигурацию я проверял на ВМ, а доступность TCP и HTTP — также с Windows-хоста. Проверка `config` запускает `nginx -t` и требует root. Я использовал только стандартную библиотеку Python.

## С чем столкнулся

Я различал подтверждённый отказ (`fail`, код 1) и невозможность выполнить проверку (`error`, итог `unknown`, код 3). На Windows нет `systemctl`, поэтому такая проверка службы не означает, что Nginx на ВМ остановлен. Если в одном запуске есть и `fail`, и `error`, текущая утилита отдаёт приоритет коду 1.

При ошибке конфигурации reload завершился неуспешно, но сайт продолжил отвечать. После restart та же ошибка уже не позволила запустить Nginx. При блокировке firewalld локальный запрос также оставался успешным, поэтому я проверял доступность с хоста.

В сценарии SELinux обычный `ls -Z` получил `Permission denied`; тип файла до исправления я подтвердил записью AVC. Сбой диска я имитировал повышением порога, а не заполнением файловой системы.

Я восстановил запускавшийся скрипт с ВМ, затем удалил комментарии и docstring. Исторические проверки относятся к версии с SHA-256 `c9b8e118…`, текущий файл — к версии `f76c77f6…`; обе записи приведены отдельно. В ранних записях функция `rec` не сохраняла кавычки, позже я исправил вывод команды через `%q`.

## Воспроизводимость

Исходный код находится в [src/diagnose.py](src/diagnose.py), действия и результаты — в [журнале работы](docs/work-log.md). Я сохранил команды, вывод и коды завершения в `evidence/`; сырые записи из `raw/` не публикую.

Для публикации я заменил адреса стенда адресами из документационного диапазона `192.0.2.0/24`, имя администратора — на `admin`, имя пользователя Windows — на `user`, отпечатки ключей — на `SHA256:<fingerprint>`. Эти адреса не предназначены для подключения к стенду.
